# Dependency audit: hono 4.13.13 and rustls 0.23.45

Human lockfile bump. Existing Dependabot pull requests do not reach the
patched versions, so the audit-trail gate applies.

Dependabot #10 stops at rustls 0.23.43, which is still inside
GHSA-2mjx-qc3c-rqvc (`>= 0.23.13, < 0.23.45`). Dependabot #1, #8, and #9
do not move hono off 4.13.7. None of those pulls were merged.

## Which dependencies changed and why

npm lockfiles. `npm update hono --package-lock-only --ignore-scripts`
resolved the existing `^4` and `^4.11.4` ranges to 4.13.13. No
`package.json` changed. 4.13.11 is the first release that patches
GHSA-5r4p-p66f-jhc7. 4.13.13 is the latest 4.x on that range and was
published 2026-10-04, outside the 7-day cooling-off window. 4.13.12
(2026-09-30) is also cooled. The lockfiles take 4.13.13 because that is
what the package manager resolves.

| Lockfile | Package | From | To |
|---|---|---|---|
| `agent-governance-python/agent-mesh/packages/mcp-proxy/package-lock.json` | hono | 4.13.7 | 4.13.13 |
| `agent-governance-python/agent-os/extensions/mcp-server/package-lock.json` | hono | 4.13.7 | 4.13.13 |
| `agent-governance-python/agentmesh-integrations/mastra-agentmesh/package-lock.json` | hono | 4.13.7 | 4.13.13 |
| `policy-engine/sdk/node/package-lock.json` | hono | 4.13.7 | 4.13.13 |

Cargo lockfiles. `cargo update -p rustls --precise 0.23.45`, then precise
pins for the transitive crates rustls 0.23.45 requires. rustls 0.23.45
was published 2026-09-14.

| Lockfile | Package | From | To | Why |

| `policy-engine/Cargo.lock` | aws-lc-rs | 1.17.0 | 1.18.0 | rustls 0.23.45 requires `^1.18` |

rustls-webpki 0.103.16 was the crates.io latest on 2026-10-20 and was
published that same day, inside the cooling-off window. 0.103.15
(2026-08-21) satisfies the new floor. aws-lc-rs 1.18.2 / aws-lc-sys
0.46.0 also satisfy the ranges. 1.18.0 (2026-08-07) and aws-lc-sys 0.44.0
(2026-08-07) are the minimum cooled pair, so the native crypto bump stays
there. `cargo metadata --locked` on Rust 1.89 accepts all three lockfiles.

The benchmark lock also moved `agent-control-spec` from 0.4.0-alpha.3 to
0.4.0-alpha.4. `policy-engine/sdk/rust/Cargo.toml` already pins
`=0.4.0-alpha.4`. The previous benchmark lock failed
`cargo metadata --locked` against that pin. Cargo rewrote the lock while
updating rustls. alpha.4 was published 2026-09-26. The rewrite drops
`serde_yaml` 0.9.34, `ryu` 1.0.23, and `unsafe-libyaml` 0.2.11, and adds
`serde_path_to_error` 0.1.20 (published 2025-09-15) plus `thiserror` /
`thiserror-impl` 2.0.21 (published 2026-09-23).

Python hash lock. `agent-governance-python/agent-os/services/cloud-board/requirements.lock`
pinned `aiohttp==3.13.3` after `requirements.txt` moved to 3.14.4 in the
previous cloud-board bump. The hash block now matches 3.14.4. PyPI
published that release on 2026-10-05. No other manifest in this repo
exact-pins aiohttp at 3.14.3 or below. Dependabot alerts 187, 188, and
189 still report `requirements.txt` as `= 3.14.3`. That file on main is
already `==3.14.4`, so those three alerts are waiting for Dependabot to
scan the file again.

## Security advisory relevance

- Alerts #190, #191, #192, and #195. `GHSA-5r4p-p66f-jhc7` (medium).
  `serveStatic` decodes the request path a second time, so middleware that
  matched the once-decoded path can be bypassed. Fixed in hono 4.13.11.
  These lockfiles now resolve 4.13.13. hono is transitive through
  `@modelcontextprotocol/sdk` (`hono: ^4.11.4`) and `@hono/node-server`
  (`hono: ^4`). Alerts #190 and #191 are runtime scope. #192 and #195 are
  development scope.
- Alerts #193, #194, and #181. `GHSA-2mjx-qc3c-rqvc` (medium). rustls
  accepted some TLS 1.3 handshake messages across a change of encryption
  key. Fixed in 0.23.45. #193 and #194 are the manifests named for this
  fix. #181 is the same advisory on `policy-engine/Cargo.lock`.
- Alerts 187, 188, and 189 stay open until GitHub scans
  `requirements.txt` again. The vulnerable exact pin that was still in tree was
  the cloud-board hash lock at 3.13.3. Advisory details are in
  [2026-10-20-cloud-board-aiohttp-3.14.4.md](2026-10-20-cloud-board-aiohttp-3.14.4.md).

## Breaking change risk assessment

Risk is low for the hono and rustls patch bumps, and higher for the
benchmark lock's agent-control-spec reconciliation only in the sense that
the lock now matches a pin the Rust SDK already declared.

- hono 4.13.13 is a patch on 4.13.x. No package.json range changed. Call
  sites do not import hono directly. The previous
  [2026-09-15-hono-node-server-2.md](2026-09-15-hono-node-server-2.md)
  audit still describes where `@hono/node-server` is loaded.
- rustls 0.23.45 is a patch on 0.23.x. The aws-lc-rs move is 1.17 to
  1.18, required by the new rustls floor, not a jump to 1.18.2. rustls
  remains a transitive TLS dependency of the benchmark harness, the
  coding-agent example, and the policy-engine workspace.
- agent-control-spec 0.4.0-alpha.4 is not a new manifest constraint. The
  benchmark lock was behind `policy-engine/sdk/rust`. Leaving alpha.3 in
  that lock keeps `cargo metadata --locked` failing.
- aiohttp 3.14.4 in the hash lock matches the requirements.txt pin
  already on main. cloud-board uses aiohttp as a client. Rollback of the
  hash lock alone would not change the installed pin from requirements.txt.

Rollback is reverting these lockfiles. That would reopen the hono and
rustls alerts, and it would put the benchmark lock out of date with the
agent-control-spec pin again.
